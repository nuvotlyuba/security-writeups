# Lab: Server-side template injection using documentation

**Платформа:** PortSwigger Web Security Academy  
**Категория:** Server-Side Template Injection (SSTI)  
**Сложность:** Practitioner  
**Дата:** 2026-08-10

## TL;DR

Приложение уязвимо для внедрения шаблонов на стороне сервера (SSTI) из-за небезопасного использования шаблонизатора FreeMarker. Пользовательский ввод из параметра поиска отражается в HTML-странице и обрабатывается как код шаблона. Обнаружив синтаксис `${...}` и убедившись в его вычислении, был идентифицирован движок FreeMarker. Используя встроенный класс `freemarker.template.utility.Execute` с оператором `?new()`, удалось выполнить произвольную команду ОС и удалить файл `morale.txt` из домашнего каталога пользователя `carlos`.

---

## Описание уязвимости

Приложение отражает пользовательский ввод в тексте сообщения о наличии товара на странице продукта. Значение из пользовательского запроса подставляется напрямую в шаблон FreeMarker до его рендеринга, что позволяет внедрить произвольный код шаблона.

FreeMarker — шаблонизатор на основе Java, использующий синтаксис `${expression}` для вывода результата вычисления выражений и `<#directive>` для управляющих конструкций. Так как FreeMarker выполняется на JVM, через специальный класс `Execute` он предоставляет прямой доступ к системным командам операционной системы.

## Разведка

### Шаг 1 — Обнаружение точки отражения пользовательского ввода

Трафик перехвачен через Burp Suite. При просмотре страницы товара было замечено сообщение о количестве оставшихся единиц:

```
Hurry! Only ${product.stock} left of ${7*7} at ${product.price}.
```

В тексте ответа вместо `${7*7}` отобразилось число `49`. Это означает, что выражение внутри `${...}` было **вычислено сервером**, а не просто отражено как текст. Сама конструкция `${...}` попала в отображаемое сообщение из пользовательского ввода в параметре поиска.

![Обнаружение точки отражения пользовательского ввода](./images/03-01-first-payload.md)

### Шаг 2 — Идентификация шаблонизатора

Синтаксис `${expression}` характерен для нескольких шаблонизаторов, однако контекст Java-приложения и поведение вычисления выражений указывали на **FreeMarker**. Для подтверждения была использована встроенная переменная FreeMarker:

```
${.engine_name}
```

**Результат:** на странице отобразилась строка `FreeMarker` — движок подтверждён.

> **Примечание:** попытка использовать Java-синтаксис вызова метода (`${"freemarker".toUpperCase()}`) не сработала — FreeMarker использует собственные встроенные операторы через `?`, а не прямые Java-методы. Правильный эквивалент: `${"freemarker"?upper_case}`.

![Идентификация шаблонизатора](./images/03-02-engine-name.md)

## Эксплуатация

### Шаг 3 — Поиск способа выполнения произвольного кода

Изучена документация FreeMarker. Обнаружен оператор `?new()`, который позволяет создавать экземпляры Java-классов напрямую из шаблона. В стандартной поставке FreeMarker присутствует класс `freemarker.template.utility.Execute`, предназначенный для выполнения произвольных команд операционной системы.

Синтаксис вызова:

```
${"freemarker.template.utility.Execute"?new()("команда")}
```

Здесь:

- `"freemarker.template.utility.Execute"?new()` — создаёт экземпляр класса `Execute`
- `("команда")` — немедленно вызывает его как функцию, передавая shell-команду

### Шаг 4 — Проверка выполнения команды

Для подтверждения возможности выполнения команд ОС был отправлен тестовый payload:

```
${"freemarker.template.utility.Execute"?new()("id")}
```

**Результат:** на странице отобразился вывод команды `id`, содержащий информацию о текущем системном пользователе. RCE подтверждён.

![Проверка выполнения команды](./images/03-03-id.md)

### Шаг 5 — Формирование финального payload

Составлен payload для удаления целевого файла:

```
${"freemarker.template.utility.Execute"?new()("rm /home/carlos/morale.txt")}
```

### Шаг 6 — Отправка payload и подтверждение эксплуатации

Payload подставлен в уязвимый параметр запроса и отправлен через Burp Repeater. При обработке шаблона сервер создал экземпляр класса `Execute` и выполнил команду `rm /home/carlos/morale.txt`. Файл был удалён из домашнего каталога `carlos`. Лаборатория отмечена как решённая (статус "Solved").

![Отправка payload и подтверждение эксплуатации](./images/03-04-final-payload.md)

## Итог

Приложение оказалось уязвимо к SSTI из-за небезопасной подстановки пользовательского ввода в шаблон FreeMarker. Синтаксис `${7*7}` → `49` однозначно идентифицировал движок. FreeMarker предоставляет прямой доступ к Java-классам через оператор `?new()`, что позволило создать экземпляр класса `Execute` из стандартной библиотеки FreeMarker и выполнить произвольную команду ОС без каких-либо дополнительных обходов защиты. Уязвимость была эксплуатирована в три шага: идентификация движка → поиск класса Execute в документации → выполнение команды удаления файла.

## Защита

Для предотвращения подобных атак необходимо:

- не подставлять пользовательский ввод напрямую в код шаблона — передавать данные только через контекст переменных, а не через конкатенацию строк с исходным кодом шаблона;
- ограничить возможности шаблонизатора: в FreeMarker отключить или ограничить доступ к классам Java через `Configuration.setNewBuiltinClassResolver()` с использованием `TemplateClassResolver.SAFER_RESOLVER` или `TemplateClassResolver.ALLOWS_NOTHING_RESOLVER`, который запрещает создание экземпляров любых классов через `?new()`;
- применять строгую валидацию и санитизацию пользовательского ввода перед его использованием в шаблонах;
- запускать шаблонизатор с минимальными системными привилегиями (принцип наименьших привилегий), чтобы ограничить последствия выполнения произвольного кода;
- рассмотреть переход на «logic-less» шаблонизаторы (например, Mustache), которые не поддерживают выполнение произвольного кода по своей природе.
